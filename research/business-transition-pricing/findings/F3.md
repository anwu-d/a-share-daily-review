# F3: 投资者关系问答平台（深交所互动易 irm.cninfo.com.cn / 全景网 ir.p5w.net）的数据契约：关键词检索、单公司全量问答、答案正文与时间戳的真实请求形状

> 方法说明：本文件所有接口形状均来自**实际发请求**（Python requests，无 Cookie、无登录），并同时用官方前端打包产物（`https://irm.cninfo.com.cn/app.67c497b19f5603f34c74.js` 及路由 chunk、`https://ir.p5w.net/resources/js/**`）的代码原文交叉验证。文中 `quote` 为逐字引用（JS 片段或 API 原文），`totalRecord/total` 为实测返回值。复现机器为 Windows + `E:\Project\stock\.venv`。

## Findings

### [1] 互动易真正的 XHR 基址是 `https://irm.cninfo.com.cn/newircs`，而页面里的 `window.IRCS_API='//irm.cninfo.com.cn/ircs'` 只是 SPA 路由前缀——两者混用是"接口 405/500"的常见原因

- url: https://irm.cninfo.com.cn/app.67c497b19f5603f34c74.js
- source_type: primary
- published: unknown（打包文件名带内容哈希，2026-09 实抓）
- confidence: high

### [2] 关键词搜索端点是 `POST /newircs/index/search`，参数必须放在 **form-urlencoded body**；传 JSON body 会被完全忽略（返回全量 72928 条，与 keyWord 无关）
- quote: `{url:"/index/search",method:"post",data:Object(r["a"])(Object(r["a"])({},t),{},{highLight:e}),headers:{sendType:"formdata"}}`
- url: https://irm.cninfo.com.cn/app.67c497b19f5603f34c74.js
- source_type: primary
- published: unknown
- confidence: high
- 实测对照：JSON body（`searchTypes:"1,11"`、`keyWord:"固态电池"`）→ `totalRecord=72928`；同样内容用 form-urlencoded → `totalRecord=362`。请求拦截器把 `sendType:"formdata"` 翻成 URL 编码：
  `t.headers["Content-Type"]="formdata"===e?"application/x-www-form-urlencoded":"application/json;charset=utf-8"`

### [3] `POST https://irm.cninfo.com.cn/newircs/index/search` 的正确参数集与实测结果（form-urlencoded，缺省 `searchTypes` 时等价于全部问答）
- quote: `{"pageNo": 1, "pageSize": 5, "searchTypes": "1,11", "keyWord": "固态电池", "highLight": "true"} -> totalRecord 362 totalPage 73`
- url: https://irm.cninfo.com.cn/newircs/index/search
- source_type: primary
- published: 实测于 2026-09-18
- confidence: high
- 参数：`pageNo`(从 1 起)、`pageSize`(实测 1→500 均生效，且 `pageSize=500` 单次返回 362 条)、`searchTypes`(逗号字符串)、`keyWord`、`highLight`(布尔，控制 `<em>` 高亮)；可选 `stockCode`、`beginDate`/`endDate`。响应：`{pageNo,pageSize,totalRecord,totalPage,results[],count}`，`results[]` 字段含 `indexId/contentType/mainContent/pubDate/stockCode/secid/companyShortName/attachedContent/attachedPubDate/attachedId/authorName/qaStatus`。
- **原始探针返回 `totalRecord:0` 的根因已定位**：把数组写成字符串 `searchTypes='[1,2,3]'` 时空结果。实测 `searchTypes='[1,2,3]' → 0`、`'1' → 55`、`'1,11' → 362`、`'' → 362`；`searchTypes:[1,2,3]` 这种 JSON 数组同样不接受。

- url: https://irm.cninfo.com.cn/interactiveAnswer.b162970a7130ec54d1c0.js（`/resources/js/homepage/home.js` 亦同）
- source_type: primary
- published: unknown
- confidence: high
- 实测（`keyWord='公司'`）：`1→10002`、`11→58660`、`1,11→68662`、`2→6180`、`3→1000`、`4→1000`、`5→0`、`6→0`、`7→51`、`5,6,7→51`、`12/13→0`；返回的 `contentType` 与所请求的值一致。前端类目映射为 `E={survey:"4",voice:"2",notice:"3",4:"survey",2:"voice",3:"notice"}`，首页调研列表硬编码 `{pageNo:1,pageSize:4,searchTypes:"4"}`。

### [5] 取单公司全量问答用 `POST /newircs/company/question`，参数放在 **query string**（不是 body）：`_t,stockcode,orgId,pageSize,pageNum,keyWord,startDay,endDay`；实测 `pageSize=1000` 一次取回全部 168 条
- quote: `POST https://irm.cninfo.com.cn/newircs/company/question?_t=...&stockcode=300857&orgId=9900039793&pageSize=1000&pageNum=1&keyWord=&startDay=&endDay= -> {"pageNo":1,"pageSize":1000,"total":168,"totalPage":1,"rows":[...168 items...]}`
- url: https://irm.cninfo.com.cn/newircs/company/question
- source_type: primary
- published: 实测于 2026-09-18
- confidence: high
- 前端同源定义：`function u(t){return Object(r["a"])({url:"/company/question",method:"post",params:t})}`（`params` 即 query string）；页面组件的请求体为 `{stockcode,orgId,pageSize:10,pageNum,keyWord:keyWordValue,startDay,endDay}`。
- `keyWord` 在本接口内可做单公司内检索：实测 `keyWord=算力` → `total=81`；`keyWord=固态电池` → `total=0`。`pageNum` 从 1 起。

### [6] `orgId` 必须先用 `POST /newircs/index/queryKeyboardInfo`（form: `keyWord=<代码或简称>`）换取 `secid`；在全局搜索里按公司过滤时 `stockCode` 必须写成 `orgId_stockCode`
- quote: `POST https://irm.cninfo.com.cn/newircs/index/queryKeyboardInfo  data={"keyWord":"300857"} -> {"statusCode":200,...,"data":[{"stockCode":"300857","shortName":"协创数据","pinyin":"XCSJ","stockType":"S","secid":"9900039793"}]}`
- url: https://irm.cninfo.com.cn/newircs/index/queryKeyboardInfo
- source_type: primary
- published: 实测于 2026-09-18
- confidence: high
- 实测：`/index/search` 里 `stockCode='300857'` → `totalRecord 0`；`stockCode='9900039793_300857'` → `totalRecord 168`（与 `/company/question` 的 168 完全一致）。前端同规则拼装：`this.stockCode=t.secid+"_"+t.stockCode`（`interview.js`）。

### [7] 答案正文与问答时间戳的字段：问 = `mainContent` + `pubDate`，答 = `attachedContent` + `attachedPubDate`（毫秒时间戳）；但 `/company/question` 的回答时间经常为 `null`，应以 `updateDate` 兜底，权威值取 `/newircs/question/getQuestionDetail?questionId=<indexId>` 的 `replyDate`
- quote: `{"indexId":"2359968848940838912","mainContent":"董秘您好，公司拟申请新增400亿元综合授信额度...","pubDate":1789472534000,"attachedId":"2361503277520277504","attachedContent":"您好，公司已回复过类似问题，烦请您查阅此前发布的相关回复内容。感谢您的关注。","attachedPubDate":null,"updateDate":1789651203000,"qaStatus":"2"}`
- url: https://irm.cninfo.com.cn/newircs/company/question?stockcode=300857&orgId=9900039793&pageSize=1000&pageNum=1
- source_type: primary
- published: 实测于 2026-09-18
- confidence: high
- 对照：同一批 168 条中 147 条有 `attachedContent`，但抽样 3 条的 `attachedPubDate` 全为 `null`，`updateDate` 明显等于回复时间；而在 `/index/search` 的结果里 `attachedPubDate` 是**有值**的（如 `attachedPubDate:1789651128000`）。因此"只从列表页拿回答时间"会踩坑。
- 详情接口原文：`GET https://irm.cninfo.com.cn/newircs/question/getQuestionDetail?questionId=2359968848940838912` → `{"statusCode":200,"message":"获取问答详情成功","data":{"questionContent":"...","questioner":"irm2845048","questionDate":1789472534000,"stockCode":"300857","shortName":"协创数据","secId":"9900039793","replyContent":"您好，公司已回复过类似问题...","replyDate":1789651204000,"historyList":[]}}`；`questionDate`/`replyDate` 均为毫秒 epoch，`pubDate` 同为毫秒（`pd.to_datetime(..., unit="ms")` 可直接转北京时间）。

### [8] 只读接口**不需要登录、token、Cookie、Referer 或 `X-Requested-With`**；但 SPA 会带 `_t` 时间戳（`Date.parse(new Date)/1000`）与 `X-Requested-With: XMLHttpRequest`，且 `newircs/search/searchResult` 是需登录的页面级接口
- quote: `t.params=Object(r["a"])({_t:Date.parse(new Date)/1e3},t.params)` ／ `bare UA POST -> 200 362`
- url: https://irm.cninfo.com.cn/app.67c497b19f5603f34c74.js
- source_type: primary
- published: 实测于 2026-09-18
- confidence: high
- 实测：去掉 `X-Requested-With` 与 `_t`、只留 `User-Agent: Mozilla/5.0` 的裸 POST，`/index/search` 仍返回 200 且 `totalRecord=362`；`/company/question`、`/question/getQuestionDetail`、`/index/queryKeyboardInfo` 同样可用。
- 唯一需登录的读取路径：前端标注 `function l(t){return Object(a)({url:"/search/searchResult",method:"get",needLogin:!0,params:t})}`；未登录 `GET /newircs/search/searchResult` 返回 500，`POST` 返回 405（说明它是 GET 的页面接口，不是 JSON API）。提问/点赞/收藏等写接口标注 `needLogin:!0`，与本模块无关。

- published: 2024-05-20（文件头 `Date: 2024/5/20`）

## Dead ends
- `https://html.duckduckgo.com/html/?q=...`：本机直连超时（WinError 10060），无法作为检索通道。
- Bing 中文检索 `github 互动易 irm.cninfo.com.cn 爬虫 接口`：返回全是 GitHub 官网/镜像站/知乎教程，无任何接口级信息。
- `https://raw.githubusercontent.com/akfamily/akshare/main/...`：连接被中断/超时；改用 `cdn.jsdelivr.net/gh/...` 镜像才拿到源码。
- GitHub 仓库搜索 `q=全景网 互动 爬虫`：结果被无关巨型 README 仓库污染（top1 为政治宣传库），无可用客户端。
- `POST https://irm.cninfo.com.cn/newircs/index/search` + JSON body：HTTP 200 但参数被静默丢弃（返回全量 72928），一度看起来"端点不可用"——实为 Content-Type 陷阱，已解决。
- `https://wxly.p5w.net/api/data/{gettrssearch,getinvestigatelist,getresearchreportlist,getinterimannouncementlist}`（全景网公司页 JS 里出现的检索/调研/研报接口）：无论 form 还是 JSON 体，一律返回 HTML 应用外壳，未能探出契约；如需"机构调研/研报"维度建议另找数据源。
- `searchTypes=3`（公告）与 `searchTypes=4`（调研）在实测中 `totalRecord` 恒为 1000（疑似 ES 结果窗口封顶），无法确认是真实总量还是截断值。
- 全景网 `/search/toSearchResult.shtml` 与 `/search/getSearchResult.shtml`：400，且带 `searchValue` 参数无效；站内搜索只能走 finding 11 的 `getNewSearchQ/R`。

## Suggested follow-ups
- 互动易 `searchTypes=3/4` 的 `totalRecord=1000` 是否为 ES `result_window` 上限？若确为截断，单公司/单关键词的公告与调研证据会不全，需要按日期切片（`beginDate/endDate` 是否对该两类生效）规避。
- `/company/question` 的 `attachedPubDate` 何时为 null（是否只对"多次追问/置顶/追问合并"的条目为 null）？确认后决定是否必须对每条 `qaStatus=2` 的问答都补一次 `getQuestionDetail`（会带来 1 次/条的请求放大）。
- 全景网 `getNewSearchR` 的 `total=100` 封顶是硬上限还是默认 `rows` 影响的结果？用 `rows=100`+翻页试探，判断能否用于覆盖某公司全部历史回答。
