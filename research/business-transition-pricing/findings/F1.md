# F1: cninfo 巨潮公告检索端点 `hisAnnouncement/query` 的完整请求/响应契约

> 方法说明：本节全部结论来自 2026-09-18 在本机对 `http://www.cninfo.com.cn/new/hisAnnouncement/query` 的**实测**（约 200 次真实请求，Python `requests` 2.34.2，`E:\Project\stock\.venv`），外加巨潮自己前端 JS 的源码与一个独立开源客户端（akshare）的交叉验证。凡标 `primary` 者均为巨潮官方端点/官方 JS/官方数据文件本身。

## Findings

### [1] 该端点只接受 POST 表单，且**必须**带浏览器 User-Agent；不需要任何 Cookie、不需要 Referer，也不是封 IP 的强限流接口
- quote: `no UA             : 403 ct=text/html NONJSON '<!doctype html><html><head><meta charset=utf-8><title>403 Fo'` / `requests default UA: 403` / `no Referer        : 200 ct=application/json;charset=UTF-8 total=1980 n=30` / `GET not POST       : 500 text/html;charset=utf-8` / `== rate limit: 40 rapid sequential requests == elapsed 4.7s statuses: {200: 40}`
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown（端点行为于 2026-09-18 实测）
- confidence: high

### [2] `pageSize` 的**服务端硬上限是 30**：请求 50/100/200/1000 一律只返回 30 条，且 0/-1/31/"abc"/"" 等非法值被静默当作 30，不报错
- quote: `50 returned 30 total 1980` / `1000 returned 30 total 1980` / `== pageSize edge == 0 {...'n':30,'totalpages':66} -1 {...'n':30} 31 {...'n':30} 'abc' {...'n':30} '' {...'n':30}`（同时 akshare 客户端也固定写死 `"pageSize": "30"`）
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown
- confidence: high

### [3] 分页有两个致命陷阱：`pageNum ≥ 101` 会**静默返回第 1 页**（不是报错、不是空），而 `pageNum` 合法但越过真实末页时 `totalAnnouncement` 会被**归零**，因此不能用"翻到空页为止"的循环
- quote: `pageNum 100 (0, 0, 0, None)` / `pageNum 101 (1980, 66, 30, '关于公司控股股东、实际控制人签署《股权转让协议》')` / `pageNum=   100 n= 30 total=397246 first=1225565642` / `pageNum=   101 n= 30 total=397246 first=1225570949`（101 与第 1 页首条 announcementId 完全相同）
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown
- confidence: high

### [4] 响应顶层固定 8 个字段，`totalAnnouncement == totalRecordNum` 是**过滤后**的真实总数，`totalpages = ceil(total/30)`，末页 `hasMore=false`；空结果时 `announcements` 是 `null` 而不是 `[]`
- quote: `{"classifiedAnnouncements":null,"totalSecurities":0,"totalAnnouncement":0,"totalRecordNum":0,"announcements":null,"categoryList":null,"hasMore":false,"totalpages":0}` / `top-level keys: ['classifiedAnnouncements', 'totalSecurities', 'totalAnnouncement', 'totalRecordNum', 'announcements', 'categoryList', 'hasMore', 'totalpages']` / `pageNum 66 {'total': 1980, 'n': 30, 'totalpages': 66, 'hasMore': False}`
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown
- confidence: high

### [5] 单条记录 23 个字段；`announcementTime` 是**北京时间零点的毫秒时间戳**（非精确披露时刻），`announcementId` 即 PDF 文件名，PDF 地址 = `http://static.cninfo.com.cn/` + `adjunctUrl`，`adjunctSize` 单位为 KB
- quote: `{'secCode': '603001', 'secName': '奥康国际', 'orgId': '9900022510', 'announcementId': '1225570949', 'announcementTime': 1789660800000, 'adjunctUrl': 'finalpage/2026-09-18/1225570949.PDF', 'adjunctType': 'PDF', 'adjunctSize': 217, 'columnId': '250401||251302', 'pageColumn': 'SHZB', ...}` 且 `1789660800000 2026-09-17 16:00:00 UTC | local: 2026-09-18 00:00:00`，以及 `adjunctSize= 217 KB vs bytes= 220825 => 222208 expected if KB`
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown
- confidence: high

### [6] 官方合法 `category` 共 26 个（巨潮前端 JS 与 akshare 完全一致），多选分隔符是**分号 `;`**（逗号或空格分隔会让整个过滤器失效）
- quote: `{"key": "category_gqjl_szsh", "value": "股权激励"}`、`{"key": "category_rcjy_szsh", "value": "日常经营"}`、`{"key": "category_fxts_szsh", "value": "风险提示"}`、`{"key": "category_gqbd_szsh", "value": "股权变动"}`；JS 中 `function getParams(checked) { return checked.map(function (item) { return item.key }).join(';') }`；实测 `'category_gqjl_szsh;category_gszl_szsh' (16955)` vs `'category_gqjl_szsh,category_gszl_szsh' (153372)`
- url: http://static.cninfo.com.cn/new/js/app/disclosure/notice/history-notice.js?v=20231124083101
- source_type: primary
- published: 2023-11-24（文件版本号 `?v=20231124083101`）
- confidence: high

### [7] 反直觉陷阱：**非法的 `category` 或 `plate` 值被静默忽略并返回全市场数据**（不报错），而非法的 `tabName` 返回 0 条 —— 因此每类查询都必须先核对 `totalAnnouncement` 是否合理
- quote: `category_diaoyan_szsh {'total': 153372, ...}`（= 完全不筛）、`category_gqjl_bf {'total': 153372, ...}`（= 同不筛）、`'ipo' {'total': 1980}`（plate 非法 = 同不筛）；对比 `'xyz' {'total': 0, 'n': 0}`（tabName 非法直接 0 条）
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query
- source_type: primary
- published: unknown
- confidence: high

### [8] `column` 只有 `szse`（深沪京 A 股）/`hke`/`fund`/`bond` 四个值真正生效；空字符串 = 全部市场；`regulator`/`third`/`pre_disclosure` 在本端点一律返回 0 条（akshare 的 column_map 列了这三个值，直接用会拿到空表）
- quote: `'szse' (397246...)` / `'hke' (92254, 3075...)` / `'fund' (17432...)` / `'bond' (15302...)` / `'' (2849...)` / `'regulator' (0, 0, 0, None)` / `'third' (0, 0, 0, None)` / `'pre_disclosure' (0, 0, 0, None)`；JS 中 `marketTab = { szse: '深沪京', hke: '港股', fund: '基金', bond: '债券' }`
- url: http://www.cninfo.com.cn/new/hisAnnouncement/query

- published: unknown

### [9] `plate` 只有 7 个合法值 `sz`/`szmb`/`szcy`/`sh`/`shmb`/`shkcp`/`bj`，且**创业板的值是 `szcy` 而不是 `ipo`**（`ipo` 会被静默忽略并返回全市场）；板块数可完全对上：1004+894+82=1980

### [10] `seDate` 格式为 `YYYY-MM-DD~YYYY-MM-DD`（`~` 两侧空格可容忍，也支持单日 `2026-09-17`）；**格式错误时静默返回 0 条而非报错**，只有用 `-` 作分隔符才会 500；缺一端（akshare 示例里的 `2026-09-01~`）返回 0 条
- quote: `'2026-09-17 ~ 2026-09-18' (1980...)` / `'2026-09-17' (1183...)` / `'2026/09/17~2026/09/18' (0, [])` / `'20260917~20260918' (0, [])` / `'2026-09-17-2026-09-18' ('ERR', 500)` / `'2026-09-01~' (0, 0, 0, None)`

## Dead ends

- `https://html.duckduckgo.com/html/?q=...` 两次均 `Transport error`，DDG 在本机不可用。
- `https://www.bing.com/search?q="hisAnnouncement/query"+巨潮+接口参数` 返回 50 条完全不相关的抖音词条，无任何可用内容，已弃用。
- `raw.githubusercontent.com/akfamily/akshare/main/...` 连接被重置（RemoteDisconnected）；改走 `api.github.com/repos/.../contents/...` 才取到源码。
- `http://www.cninfo.com.cn/new/commonUrl?url=disclosure/list/hisAnnouncement` 返回 500，历史公告页只能通过 `?url=disclosure/list/search` 或 `pageOfSearch` 入口访问，无法直接取到该页 HTML。
- `http://www.cninfo.com.cn/new/disclosure/stock?tabName=data&orgId=..&stockCode=..` POST 返回 500、GET 返回 HTML 页面，不是 JSON API（按个股取数请用 `hisAnnouncement/query` 的 `stock` 参数）。
- `POST /new/fulltextSearch/accurateTitleSearch` 返回 404（JS 里引用了该路径但已下线）。
- `searchkey="半固态电池"`、`searchkey="半固态"` 在 `hisAnnouncement/query` 命中 0 条，说明该参数不搜正文；正文级检索必须换用 `GET http://www.cninfo.com.cn/new/fulltextSearch/full?isfulltext=true`（实测 `批量生产` 在该端点 1333 条，但 `isfulltext=false` 为 0，且首页结果出现"股票交易异常波动公告"这类明显不相关命中，相关性很差，且 `pageNum>100` 同样返回 0）。

## Suggested follow-ups

- `GET /new/fulltextSearch/full` 的完整契约（`sdate`/`edate`/`isfulltext`/`type` 语义、100 页上限、相关性排序是否可靠）值得单独一轮实测——它可能是判断"批量生产/送样"等里程碑措辞的唯一来源。
- `isHLtitle=true` 时若标题本身含 `<em>` 之外的特殊字符，`announcementTitle` 会被改写；建议实测增量拉取时用 `announcementId` 而非标题做去重键（`announcementId` 在实测中稳定且等于 PDF 文件名）。
- `category` 在 `tabName=relation` 下不起作用，那么"调研活动/媒体采访/路演活动"三类细分（`category_dyhd_szdy`/`category_mdcf_szdy`/`category_lyhd_szdy`）到底由哪个端点/参数生效，值得再查一轮（疑似只在 `column=dy` 的 "预约披露调研" 页面 `?url=data/yypl` 上生效，而该值在本端点返回 0）。
